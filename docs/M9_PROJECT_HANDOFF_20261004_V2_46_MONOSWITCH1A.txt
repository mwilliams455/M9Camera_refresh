REPORTED BEHAVIOR AND EVIDENCE
The supplied video shows the app returning to the launcher on M9 -> Monochrom and Monochrom -> M9. Reopening successfully starts the selected renderer. The supplied log has no fatal exception or native crash stack, so the exact device exception is not established by that file.

A regression test reproduces a matching switch-time failure in the 2.45 camera-screen code: an already queued preview/HUD update runs after the old fragment's onDestroy has cleared its capture controller. It throws NullPointerException in MonoIsoExpoSelector.monoHudPair1A via IsoExpoSelector.getM9LiveHudPair1A and CameraFragment.updateViewfinderHud.

FIX
Each resumed preview now owns an identity token. onPause and onDestroyView invalidate it before camera teardown. Queued HUD work checks the token before accessing the old controller. PixelCopy completion, histogram processing and histogram UI publication also reject work from the old preview, including callbacks arriving after the executor is closed. Resume creates a new token.

The renderer card's selected label is now simply Selected; Monochrom no longer displays Colour.

SETTINGS AND PHOTOGRAPHIC SCOPE
One settings hierarchy still adapts to the selected renderer. Each renderer retains its own Image controls. No changes to settings keys, capture allocator, renderer math, shaders, LUTs, output modes, DNG/JPEG processing, exposure planning, AE-L or bracketing.
All 27 native libraries and all 285 assets are byte-for-byte preserved from 2.45. Its 25 accepted M9 libraries remain the 2.38 baseline; the two Monochrom libraries are unchanged from the 2.45 integration.
